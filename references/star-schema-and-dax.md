# 星型模型 + 计算列 + 度量值 规范（维度建模 / DAX 工程实践）

> 从「爬虫宽表 + 明细表直连」升级成可交付的数据模型时照这份走。全部条款都是 2026-10 在本地 Desktop 实测过的。

## 0. 一句话原则

**事实表存"发生了什么"，维度表存"描述性属性"，度量值算"数字结果"，计算列只做静态属性。**
凡是能用度量值算的，不要用计算列（计算列占内存、刷新时才更新、不能随切片器变化）。

## 1. 表角色划分

| 角色 | 判断标准 | 本项目实例 |
| --- | --- | --- |
| 事实表 | 一行 = 一次业务事件，含可加数值 | `比赛数据`（一场一行）、`首发名单`（一人一场一行） |
| 维度表 | 一行 = 一个实体，用于切片/分组 | `维度_日期`、`维度_球队`、`维度_球员` |
| 中间查询（不加载） | 只被其他查询引用的清洗层 | `比赛宽表`（写进 `expressions.tmdl`） |

维度表**从同一条事实管道派生**（`比赛宽表` 去重 / 展开），这样爬虫丢新文件后刷新即自动同步，不用维护第二份来源。

## 2. 关系铁律（血泪）

1. **只建 事实→维度 的关系**。事实表之间**绝对不要**直连：Desktop 会报
   `"A"和"维度_X"之间存在不明确的路径` 并**拒绝打开项目**。
2. **共享维度可以同时连多张事实表**（日期维度连所有事实表 = 标准做法）。
3. **角色扮演维度**（一张维度表被同一张事实表引用两次，如主队/客队）：
   一条 `active`、另一条 `isActive: false`，配 `USERELATIONSHIP` 度量值使用。这不构成路径冲突。
4. **关系方向**默认单向（维度 → 事实）；除非确有必要，不要开双向。
5. **日期表要标记**：`维度_日期` 上加 `dataCategory: Time`，并把 Month 名称列用 `sortByColumn` 指回月份数字。

## 3. 计算列：只放静态属性

**适合**：分档、二元标记、从已有列派生的静态值。
**不适合**：任何聚合（计数/求和/占比）——那是度量值的活。

```dax
-- 二值判断
比赛数据[胜负判定] = IF ( [主队比分] > [客队比分], "主胜", IF ( [主队比分] < [客队比分], "客胜", "平局" ) )
-- 派生数值
比赛数据[分差绝对值] = ABS ( [全场分差] )
-- 分档（SWITCH(TRUE(), ...) 比嵌套 IF 好读）
首发名单[得分档位] = SWITCH ( TRUE (), [得分] >= 30, "30+", [得分] >= 20, "20-29", [得分] >= 10, "10-19", "10 以下" )
首发名单[是否得分上双] = IF ( [得分] >= 10, "是", "否" )
```

日期属性（年/季度/月份/月份名称/周数/星期/是否周末/年月）**放在维度的 M 查询里生成**，不要用 DAX 计算列——M 生成一次就固定，DAX 计算列会跟着刷新重算。

## 4. 度量值：三件套 + 工程规范

每个度量值都要有 **格式串 + 显示文件夹 + 中文描述**（`pbip_add_measures` 一次写齐）：

```json
{"name": "主场胜率", "expression": "DIVIDE ( CALCULATE ( [比赛场次], '比赛数据'[胜负判定] = \"主胜\" ), [比赛场次] )",
 "format_string": "0.0%", "display_folder": "比赛", "description": "主队获胜的场次占比（胜负判定=主胜）"}
```

**写法规范**

- 除法一律 `DIVIDE(a, b)`，不要 `a / b`（除零安全）
- 复用已有度量值（`DIVIDE ( [得分合计], [登场人次] )`），不要把表达式复制一遍
- 参照列用全限定名 `'表'[列]`，度量值用 `[度量值]`
- 复杂逻辑用 `VAR ... RETURN` 避免重复计算
- 命名：中文业务名（`场均球员得分`），不要 `m1`、`AvgScore`

**本项目 18 个度量值当模板**

| 表 | 度量值 | 表达式要点 | 格式串 |
| --- | --- | --- | --- |
| 比赛数据 | 比赛场次 | `COUNTROWS ( '比赛数据' )` | `#,##0` |
| 比赛数据 | 主场胜率 | `DIVIDE ( CALCULATE ( [比赛场次], '比赛数据'[胜负判定] = "主胜" ), [比赛场次] )` | `0.0%` |
| 比赛数据 | 场均总分 / 场均分差 | `AVERAGE ( '比赛数据'[全场总分] )` | `#,##0.0` |
| 比赛数据 | 场均分差绝对值 | `AVERAGE ( '比赛数据'[分差绝对值] )` | `#,##0.0` |
| 比赛数据 | 最大分差 / 最高单场总分 | `MAX ( ... )` | `#,##0` |
| 比赛数据 | 平均每队每场得分 | `DIVIDE ( SUM ( '比赛数据'[全场总分] ), [比赛场次] * 2 )` | `#,##0.0` |
| 首发名单 | 登场人次 | `COUNTROWS ( '首发名单' )` | `#,##0` |
| 首发名单 | 独立球员数 | `DISTINCTCOUNT ( '首发名单'[球员] )` | `#,##0` |
| 首发名单 | 得分合计 / 最高单场得分 | `SUM / MAX` | `#,##0` |
| 首发名单 | 场均球员得分 | `DIVIDE ( [得分合计], [登场人次] )` | `#,##0.0` |
| 首发名单 | 得分上双人次 | `CALCULATE ( [登场人次], '首发名单'[是否得分上双] = "是" )` | `#,##0` |
| 首发名单 | 得分上双占比 | `DIVIDE ( [得分上双人次], [登场人次] )` | `0.0%` |
| 维度_球队 | 球队数 | `DISTINCTCOUNT ( '维度_球队'[球队] )` | `#,##0` |
| 维度_日期 | 比赛日数 | `DISTINCTCOUNT ( '比赛数据'[比赛日期] )` | `#,##0` |
| 维度_日期 | 最新比赛日 | `MAX ( '比赛数据'[比赛日期] )` | `Short Date` |

## 5. 验证（改完模型必须跑）

1. `pbip_validate` → TMDL 语法 + 报告绑定
2. **打开 Desktop**（这一步才能暴露路径歧义这类"语法合法但模型不合法"的问题）
3. `desktop_execute_dax` 逐项验：
   - 维度行数：`COUNTROWS ( '维度_球队' )`
   - 关系穿透：`CALCULATE ( [比赛场次], '维度_球队'[球队] = "某队" )` —— 应能筛出该队场次
   - 度量值：`EVALUATE ROW ( "场次", [比赛场次], "胜率", [主场胜率] )`
   - 勾稽：四节加总 vs 全场，应 0 条不符
4. 刷新后 `COUNTROWS` 仍为 null = 从未刷新（不是模型错）

## 6. 看板排版约定（1280×720 画布）

- 顶部一行：4 张卡片 `(20,16,200,110)`、`(236,16,…)`、`(452,16,…)`、`(668,16,…)` + 右侧切片器 `(884,16,376,110)`
- 主体区：左大图 `(20,142,844,558)` + 右侧图 `(884,142,376,260)` / `(884,430,376,270)`
- 卡片只放**度量值**；图表的 Category/Rows 放**维度**，Y/Values 放**度量值**
- 每页一个主题（概览 / 球队 / 球员），每页一个对应切片器
