# 爬虫数据清洗模式（结构层 / 字段映射 / 名称归一 / 文本转数值 / 去重）

> 爬虫数据特有的脏，先处理结构层（0），再按顺序套字段层模式（1-5）。

## 0. Excel 结构层三招（先于一切字段操作）

爬虫导出的 Excel 经常不是「第一行表头+干净数据」，实测踩过这三个坑（2026-09-30 篮球样例）：

### 0.1 前导空行 + 双层合并表头 → 按位置映射

典型结构：第 1 行空、第 2 行大表头（合并单元格，如「全场」跨 4 列）、第 3 行子表头（主/客/分差/总分）、第 4 行起数据。`Excel.Workbook` 默认提升第一行做表头会被搞乱。**正确做法：不提升表头，跳过表头行，按位置改名**：

```
let
    // useHeaders=false：拿到 Column1..ColumnN 的原始表，所有行原样保留
    工作簿 = Excel.Workbook(Content, null, false),
    取Sheet = 工作簿{[Item="结果", Kind="Sheet"]}[Data],
    跳表头 = Table.Skip(取Sheet, 3),   // 1 空行 + 2 行表头
    按位置改名 = Table.RenameColumns(跳表头, {
        {"Column1", "序号"}, {"Column2", "比赛日期"}, {"Column4", "主队"}   // …按实际位置
    }, MissingField.UseNull)
in
    按位置改名
```

要点：列顺序稳定的爬虫导出，位置映射比解析双层表头稳得多；爬虫改列顺序了只需调这一步。注意 ColumnN 从 1 开始数。

### 0.2 尾部空行 → 先过滤，再去重

爬虫导出常带尾部空行。**空行必须在去重之前过滤掉**，否则所有空行的去重键都是 null，`Table.Distinct` 会把它们当成一批"重复行"只留一行（还可能误导重复率统计）：

```
滤空行 = Table.SelectRows(上一步, each [比赛日期] <> null)   // 用关键业务字段判空
```

### 0.3 成对列（名字+数值交替）→ 逆透视成长表

首发名单常见「球员1/得分1/球员2/得分2…」10-20 列横排。宽表留着没用，拆成长表才能做矩阵图。用内联函数按组竖拼（以主/客 × 5 顺位为例）：

```
取一边 = (主客 as text) => Table.Combine(List.Transform({1..5}, (i) =>
    let
        选 = Table.SelectColumns(源, {"编号", "比赛日期", 主客 & "队",
             主客 & "首发" & Text.From(i) & "球员", 主客 & "首发" & Text.From(i) & "得分"}),
        改名 = Table.RenameColumns(选, {{主客 & "队", "球队"}, ...}),
        加 = Table.AddColumn(改名, "顺位", each i, Int64.Type)
    in  加)),
长表 = Table.Combine({取一边("主"), 取一边("客")})
```

配套建模习惯：宽表（一场一行）+ 长表（一人一行）两张，中间用「暂存查询」承接（扫文件夹+去重只做一次），**暂存查询取消「启用加载」**。

## 1. 字段映射（列名统一）

不同爬虫/不同来源列名不一样：同一个 CC指数，可能叫 `cc`、`CC`、`ccIndex`、`CC指数`。用映射表一步批量改名：

```
let
    字段映射表 = #table(
        {"旧列名", "新列名"},
        {
            {"cc", "CC指数"},
            {"ccIndex", "CC指数"},
            {"player", "球员"},
            {"playerName", "球员"},
            {"injury", "伤病情况"},
            {"starter", "是否首发"},
            {"gameDate", "比赛日期"}
        }
    ),
    // 只保留当前表里实际存在的旧列名，避免改名报错
    有效映射 = Table.SelectRows(字段映射表, each List.Contains(Table.ColumnNames(上一步), [旧列名])),
    改名 = Table.RenameColumns(上一步, List.Zip({有效映射[旧列名], 有效映射[新列名]}))
in
    改名
```

要点：

- **禁止一列一个改名步骤**，一步搞定
- 映射表可以抽成独立的 Excel 配置文件，业务方自己维护，改映射不用动代码
- 用 `List.Contains` 过滤有效映射，来源缺某列时不报错

## 2. 名称归一（别名表）

球队/球员名称多写法是爬虫数据重灾区：「湖人」「洛杉矶湖人」「LAL」「Lakers」都是同一队。用别名表合并查询归一：

### 2.1 别名表结构（Excel 配置文件）

| 别名 | 标准名 |
|---|---|
| 湖人 | 洛杉矶湖人 |
| LAL | 洛杉矶湖人 |
| Lakers | 洛杉矶湖人 |

### 2.2 归一代码

```
let
    别名表 = Excel.Workbook(File.Contents(别名表路径), null, true){[Item="球队别名", Kind="Sheet"]}[Data],
    // 左连接：原始表的球队名去匹配别名
    合并 = Table.NestedJoin(上一步, {"球队"}, 别名表, {"别名"}, "别名匹配", JoinKind.LeftOuter),
    展开 = Table.ExpandTableColumn(合并, "别名匹配", {"标准名"}, {"标准名"}),
    // 匹配上用标准名，匹配不上保留原名（并在最后人工补别名表）
    归一 = Table.AddColumn(展开, "球队标准名", each if [标准名] = null then [球队] else [标准名]),
    清理 = Table.RemoveColumns(归一, {"标准名"})
in
    清理
```

要点：

- 匹配不上的保留原名，不丢数据
- 定期把「归一后仍不在标准名清单里」的值导出来，补进别名表
- 球员名同理（注意同名不同人的情况，归一键可以加上球队做联合键）

## 3. 文本转数值（CC指数的坑）

爬虫常把数字存成文本，还混着 `"N/A"`、`"-"`、`"23.5分"` 这类脏值：

```
let
    // 先剥掉非数字字符（"23.5分" → "23.5"），再转数值
    剥字符 = Table.TransformColumns(上一步, {{
        "CC指数",
        each Text.Select(_, {"0".."9", ".", "-"}),
        type text
    }}),
    转数值 = Table.TransformColumns(剥字符, {{
        "CC指数",
        each try Number.FromText(_) otherwise null,
        type number
    }})
in
    转数值
```

要点：

- `try ... otherwise null` 只包单字段转换，异常值变 null，不炸整表
- `Text.Select` 白名单剥字符，比 `Text.Replace` 一个个换稳
- 转完必须抽查：null 占比异常高 = 爬虫字段结构变了，去查来源

## 4. 去重（防重复导入）

爬虫重抓、同一天文件重复丢进文件夹是常态：

```
// 按业务主键去重，保留任意一行
去重 = Table.Distinct(上一步, {"比赛日期", "球员"})
```

更稳的做法——保留最新抓取的（配合来源文件列/抓取时间列）：

```
let
    排序 = Table.Sort(上一步, {{"抓取时间", Order.Descending}}),
    去重 = Table.Distinct(排序, {"比赛日期", "球员"})
in
    去重
```

要点：

- **先滤空行再去重**（见 0.2），否则 null 键互相误判为重复
- 去重键必须是业务主键（比赛日期+球员），不是整行对比——同一球员同一天数据微调过，整行对比会认为两行不同
- 有官方唯一 ID（如比赛编号）优先用 ID 做去重键，比组合键稳
- 想留最新抓取的：先按抓取时间倒序排，再去重（`Table.Distinct` 保留首次出现的行）

## 5. 缺失值标记（别急着删行）

关键字段为 null 的行，加标记列而不是删除：

```
标记 = Table.AddColumn(上一步, "数据完整性", each
    if [CC指数] = null then "缺CC指数"
    else if [伤病情况] = null then "缺伤病"
    else "完整")
```

好处：可视化里能筛选只看完整数据，同时保留排查入口——哪天空值暴涨，说明爬虫那天出问题了。

## 6. 推荐清洗总顺序

```
入口 → 结构层处理(跳表头/滤空行/拆成对列) → 字段映射(改名) → 文本清洗(Trim/Clean) → 文本转数值 → 名称归一 → 缺失值标记 → 合并多源 → 去重 → 输出
```
